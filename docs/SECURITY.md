# Security — ITSA Platform

## 1. Security Overview

Security is non-negotiable. Every design decision must consider:
- Who can access what
- How data is protected
- How inputs are validated
- How secrets are managed

---

## 2. Password Security

- **Algorithm**: Werkzeug `generate_password_hash` (PBKDF2-SHA256, 260,000 iterations)
- **Minimum requirements**: 8 characters, at least 1 uppercase, 1 lowercase, 1 digit
- **Storage**: Only the hash is stored — the plaintext password is never persisted
- **Verification**: `check_password_hash(stored_hash, provided_password)`
- **Prohibited**: Never log passwords. Never display passwords. Never store plaintext.

---

## 3. Authentication Security

- **Method**: Server-side session via Flask-Login
- **Session cookie**: `httponly=True`, `samesite=Lax`, `secure=True` (production)
- **SECRET_KEY**: Minimum 32 random characters. Stored only in `.env`
- **Session timeout**: Configurable (default 24 hours for remembered sessions)
- **Remember me**: Optional with secure persistent cookie

---

## 4. Authorization Security

- **Always server-side**: Role is read from database on each request via `current_user.role`
- **Never trust client**: Do not accept role from request body, headers, or cookies other than session
- **Role decorators**: Every protected route has `@admin_required`, `@coordinator_required`, or `@login_required`
- **Resource-level checks**: Coordinators are checked against `event_coordinators` table for each event access
- **Ownership checks**: Posts, comments, tickets, and certificates are checked for ownership before edit/delete/download

---

## 5. CSRF Protection

- HTML forms: Use Flask-WTF CSRF tokens (`{{ form.hidden_tag() }}`)
- AJAX requests: Include CSRF token in headers
- SameSite=Lax on session cookie provides baseline CSRF protection
- State-changing API endpoints never accept GET requests

---

## 6. SQL Injection Prevention

- **Primary defense**: SQLAlchemy ORM with parameterized queries (always use ORM)
- **Prohibited**: Never use raw string concatenation: `f"WHERE email = '{email}'"` is FORBIDDEN
- **Correct pattern**:
```python
user = User.query.filter_by(email=email).first()  # Safe
# NOT: db.engine.execute(f"SELECT * FROM users WHERE email = '{email}'")  # Dangerous
```
- All dynamic filters use SQLAlchemy filter expressions

---

## 7. XSS Prevention

- **Jinja2 auto-escaping**: All template variables are auto-escaped by default (`{{ variable }}`)
- **Never use**: `{{ variable | safe }}` unless the content is 100% trusted (generated by system, not users)
- **Content-Security-Policy header**: Set to restrict script sources
- **Stored XSS**: User post content stored as-is but escaped on render (never rendered as raw HTML)

---

## 8. Input Validation

- **Server-side always**: Client-side validation is UX only, never security
- **Validation layer**: All API inputs validated before service layer
- **Type checking**: Ensure correct Python types (int, str, bool, datetime)
- **Length limits**: All string fields have maximum length
- **Enum validation**: Status fields validated against allowed values
- **URL validation**: GitHub/LinkedIn URLs validated for format
- **Email validation**: Regex + uniqueness check

---

## 9. File Upload Security

| Rule | Implementation |
|---|---|
| Whitelist extensions | Check `filename.rsplit('.', 1)[1].lower()` against allowed list |
| Validate MIME type | Check file headers, not just extension |
| Secure filename | `werkzeug.utils.secure_filename(filename)` always applied |
| UUID rename | All uploaded files renamed to UUID-based names |
| Size limit | `MAX_CONTENT_LENGTH` set in Flask config |
| Never execute | Uploaded files are served as static content only |
| Access control | Files served via Flask route with auth check, not direct URL |

---

## 10. Rate Limiting

| Endpoint | Limit |
|---|---|
| POST /auth/login | 5 requests/minute/IP |
| General API | 100 requests/minute/user |
| AI Chatbot | 20 messages/hour/user |
| AI Generation | 10 requests/hour/user |
| File uploads | 20 uploads/hour/user |

**Implementation**: Flask-Limiter or in-memory counter. Return `429 Too Many Requests` with `Retry-After` header.

---

## 11. Secret Management

- ALL secrets in `.env` file: `SECRET_KEY`, `GEMINI_API_KEY`, `SMTP_PASSWORD`, `MYSQL_PASSWORD`
- `.env` is in `.gitignore` — NEVER committed
- Use `.env.example` as template (no real values)
- Rotate `SECRET_KEY` if compromised (all sessions invalidated)
- Use Render environment variables in production (not file)
- Never print or log any secret values

---

## 12. Security Headers

Add these headers to every response:

```python
@app.after_request
def set_security_headers(response):
    response.headers['X-Content-Type-Options'] = 'nosniff'
    response.headers['X-Frame-Options'] = 'DENY'
    response.headers['X-XSS-Protection'] = '1; mode=block'
    response.headers['Referrer-Policy'] = 'strict-origin-when-cross-origin'
    response.headers['Content-Security-Policy'] = (
        "default-src 'self'; "
        "script-src 'self' 'unsafe-inline' cdn.jsdelivr.net unpkg.com; "
        "style-src 'self' 'unsafe-inline' fonts.googleapis.com cdn.jsdelivr.net; "
        "font-src 'self' fonts.gstatic.com; "
        "img-src 'self' data:;"
    )
    return response
```

## 13. Audit Logging

All admin actions are logged to the `audit_logs` table:
- User suspension/unsuspension
- Points manual adjustment
- Attendance override
- Certificate revocation
- Content removal
- Account deletion

**Format**:
```python
def log_audit(user_id, action, entity_type, entity_id, details, ip):
    log = AuditLog(
        user_id=user_id,
        action=action,
        entity_type=entity_type,
        entity_id=entity_id,
        details=json.dumps(details),
        ip_address=ip
    )
    db.session.add(log)
    # Note: commit happens with the main transaction
```

---

## 14. Error Information Leakage

- **Production**: `FLASK_DEBUG=False` — no stack traces in responses
- **Error responses**: Generic messages only (`"An unexpected error occurred"`)
- **Logging**: Detailed errors logged server-side to `logs/error.log`
- **Database errors**: Never expose table names, query details, or column names to users
- **AI errors**: Never expose API keys or prompt contents in error responses

---

## 15. Data Privacy

| Data | Access Control |
|---|---|
| Passwords | Never exposed anywhere |
| Student email | Not shown in certificate verification |
| Student ID (roll number) | Only visible to owner and admin |
| QR ticket | Only accessible to ticket owner |
| Feedback content | Anonymized before AI analysis |
| Certificates | Public verification shows name/event only (no email/ID) |
